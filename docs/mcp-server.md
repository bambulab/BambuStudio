## Product scope

Bambu Studio hosts MCP directly in its normal GUI process. Preferences provides an enable switch (off by default), a port (default 27183), connection status, and local credential controls. A client connects to `http://127.0.0.1:<port>/mcp`. There is no companion application, Node runtime, patched installation, or networking-plugin dependency.

The native tool catalog mirrors the 90 names, schemas, and annotations of the existing MCP integration. It covers project preparation, geometry, slicing, preview, device planning and guarded device actions. The exact mapping and validation caveats are in [full-mcp-parity.md](full-mcp-parity.md). Printer actions and cloud-account reads are separate, default-off permissions in Preferences; physical commands still require exact task/status guards and explicit confirmation fields. Arbitrary script execution, shell commands, and unrestricted configuration writes are outside this contribution.

## Dependencies and ownership

Use the existing Boost.Asio/Beast and nlohmann JSON dependencies. `src/slic3r/GUI/HttpServer.hpp` already uses Beast. `libslic3r_gui` already links OpenSSL::Crypto, so secure token generation and comparison require no new library. Keep the MCP listener separate from the existing login/media HTTP server on port 13618.

Separate the protocol/transport from the GUI tool handler. The transport owns HTTP parsing, authentication, limits, JSON-RPC envelopes, and connection lifetime. The GUI handler owns model access, undo snapshots, busy checks, native operations, and operation state. Pure protocol tests must not require a running wxWidgets application.

## Protocol contract

Support modern MCP `2026-07-28` and a narrowly tested compatibility path for `2025-11-25`. Do not claim versions that have not been tested.

For modern requests, validate per-request protocol metadata and mirrored HTTP headers before dispatch. Implement `server/discover`, `tools/list`, and `tools/call`. Discovery advertises only implemented capabilities. Return `resultType: "complete"` and server identity in result metadata. Missing required metadata is invalid params; unsupported versions use the protocol's supported-version error. No prior request establishes authorization or version context. See [versioning](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning) and [discovery](https://modelcontextprotocol.io/specification/2026-07-28/server/discover).

For the compatibility path, accept `initialize`, `notifications/initialized`, and `ping`; negotiate the supported legacy version. Do not create a protocol session unless needed. Legacy notifications receive HTTP 202 without a JSON-RPC response. GET and DELETE may return 405 because this implementation does not expose standalone streams or server-managed sessions. See [2025-11-25 transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).

Use one POST endpoint and ordinary JSON responses. SSE, subscriptions, resources, prompts, sampling, and the Tasks extension are unnecessary for the initial tool set. Modern requests need matching `MCP-Protocol-Version`, `Mcp-Method`, and (where required) `Mcp-Name` headers; validate the specified encoded name form as well. Unknown modern methods return HTTP 404 with JSON-RPC method-not-found. Bound and reject malformed envelopes, batch arrays, null/invalid IDs, unsupported media types, and invalid parameters. See [Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http).

The transport rejects malformed request/tool-call shapes with protocol errors. The internal completion callback accepts either a raw MCP result or the reserved object `{"error":{"code":-32602,"message":"..."}}` for invalid tool names/parameters; it validates this shape and emits a JSON-RPC error instead of a successful tool response. Other domain execution failures remain tool results with `isError: true`. An operation that is understood but fails returns a tool result with `isError: true`, an actionable message, and structured state when useful. Ordinary tool results may carry explicit operation IDs for work that outlives one request. See [tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) and [protocol overview](https://modelcontextprotocol.io/specification/2026-07-28/basic).

## Local security boundary

Bind only to `127.0.0.1`. Validate Host against the configured local endpoint. Reject untrusted Origin values and do not enable permissive CORS. Require an unpredictable local bearer credential for discovery and tool calls alike. Generate at least 32 random bytes with OpenSSL; compare fixed-length values in constant time. Never place credentials in URLs, logs, project exports, presets, or cloud requests. The local credential is not OAuth: document the custom authentication strategy supported by the [protocol authorization framework](https://modelcontextprotocol.io/specification/2026-07-28/basic).

The GUI credential helper stores 32 random bytes as hexadecimal in the selected profile's `mcp.token`, separately from AppConfig. Its POSIX path uses exclusive/no-follow opening, validates ownership, and sets mode 0600. Its Windows path rejects reparse points and uses a protected DACL granting the current user access. Root/administrators and processes already running as that user remain inside this local trust boundary. Copy and regenerate controls belong to Preferences; regeneration must revoke the old listener and pending dispatch. Windows behavior still needs platform validation. Do not treat a loopback address or a client-supplied identity as authentication.

The transport limits headers to 8 KiB, bodies to 1 MiB, JSON nesting to 64 levels, and active connections to 16. HTTP reads/writes have 10-second deadlines and queued tool requests default to 30 seconds. Close rejected connections and avoid logging request bodies. Handle port conflicts visibly; never silently select another port.

## Preferences and lifetime

Persist enable/disable, the validated port, and two default-off permission flags in native AppConfig. Restrict selectable ports to 1024–65535. Apply changes live. Enabling must report bind/auth failures. A failed port change keeps the previous working endpoint. Disabling stops acceptance and revokes pending dispatch; already-started native jobs must retain honest terminal tracking. Startup starts the listener only after the editor is ready; the G-code viewer must not start it. Shutdown stops the listener before GUI dependencies disappear. MCP's `preferences_set` whitelist cannot change either permission flag.

One asynchronous I/O thread is sufficient. Network processing must never dereference wxWidgets or model objects. Post GUI work through `CallAfter` with a weak lifetime token and generation check, and post responses back to the I/O executor. Stop invalidates dispatch tokens, closes sockets, and joins an I/O thread that never waits synchronously for the GUI. A timed-out queued mutation must not execute later. A started operation must be reported as pending/failed/finished honestly, not described as canceled unless it actually stopped.

## Native operation rules

Check busy state on the UI thread immediately before a mutation. `Plater::is_any_job_running()` covers UI jobs; slicing requires a separate check. Reject concurrent mutations and unsafe modal/edit states. Reuse native mutation/update paths and undo snapshots so the canvas, object list, plate membership, dirty state, and slicing invalidation agree.

Import geometry with `LoadStrategy::LoadModel`; do not implicitly import project configuration or replace the open project. Validate paths, formats, and arguments before mutation. The legacy contract permits STL, OBJ, STEP, and geometry-only 3MF imports, plus bounded multipart STL/OBJ. File exports require explicit absolute destinations and an `overwrite` flag for replacement. Return the actual saved location and only claim success after the native operation succeeds.

`Plater::arrange()` and `Plater::reslice()` return void and can refuse work. Their return alone is not completion evidence. Long operations need an explicit accepted state and subsequent status derived from native work. Reject MCP slicing when the active preset contains nonempty `post_process` commands; do not bypass Bambu Studio's script confirmation logic or reuse a previously accepted script decision. Failed or canceled slicing must never be reported as toolpaths ready. Listener disable requests cancellation but does not claim that an already-started native operation was rolled back.

## Validation before publication

Use a new isolated test profile and fixture geometry. Do not launch against an existing user's profile or unsaved project. The locally installed production app and previous prototypes remain untouched.

The local acceptance gate includes protocol tests for both supported versions, malformed/unauthorized/hostile-origin requests, body limits, busy/timeout behavior, shutdown with pending dispatch, live enable/disable and port changes, port conflict recovery, and GUI Quit/relaunch persistence. Run a real compatible MCP client against the built application, verify all 90 tools are discoverable, and exercise representative local model, plate, geometry, preset, slice, preview, job, and export workflows. Verify state in the GUI and files, not only HTTP success. Check denied-by-default device/account calls without sending a physical or cloud action. The final-binary acceptance passes these checks, including a clipboard paste whose field value matched the copied URL. Windows/Linux CI and any physical-device/cloud validation remain separate release gates. Record unsupported platforms and remaining checks explicitly.

## Isolated transport verification

The standalone target builds without wxWidgets:

```sh
cmake -S tests/mcp -B build-mcp-tests -DCMAKE_PREFIX_PATH=<dependency-prefix>/usr/local
cmake --build build-mcp-tests -j 2
ctest --test-dir build-mcp-tests --output-on-failure
```

On 2026-10-05, AppleClang 21 compiled this target against the existing upstream Boost dependency headers and OpenSSL 3.1.2. The initial transport/credential suite passed 84 assertions. After adding cross-platform G-code export checks, the standalone target passed 93 assertions in CTest (1/1, 0.12 seconds) against the updated source. The suite verifies both protocol versions, discovery and tool dispatch, encoded tool names, rejected malformed metadata and JSON, missing/wrong/duplicate credentials, hostile Host/Origin, wrong media types, header/body limits, port conflicts, listener restart, expired queued tickets, late completion, stop with a pending request, invalid-parameter error envelopes, credential creation/persistence/rotation, and local G-code export create/overwrite/alias/stale behavior. A temporary profile verified 64-character credentials, POSIX mode 0600, symlink rejection, and rejection of a replaced token by the new listener; it was removed afterward. Listener tests require permission to bind temporary loopback ports. The test process has a 30-second CTest limit.

The Unix listener uses address reuse to permit immediate restart; Windows uses exclusive address binding. Only the macOS branch has been compiled and exercised. The standalone suite uses a fake domain callback, so it does not itself prove GUI behavior, file operations, slicing, cloud isolation of native code paths, or interoperability with a real MCP client. The separate disposable-profile run below provides bounded live evidence for local workflows and an official client; Windows platform checks remain open.
